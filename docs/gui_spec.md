## Окно

Слева - ввод, справа - результат (набросок показан автору 07.11.2026).

- **Запрос:** многострочное поле; «Примеры» (готовые запросы разных классов, как в `demo.py`) и «История» (последние 20 запросов, файл в `out/gui/history.jsonl`).
- **Переводчик:** выпадающий список - baseline; Qwen3.5-4B (локально, адаптер `out/q35_4b/adapter`); итоговая модель - когда выберем. Источник списка - `translators.REGISTRY` и файл настроек `out/gui/settings.json` (пути к адаптерам не в коде).
- **Кнопки:** «Построить» (запрос -> модель -> MC12 -> .CIR), «Пересчитать нетлист» (правленый текст -> MC12 -> .CIR, без модели), «Открыть в MC12» (готовый .CIR).
- **Нетлист:** редактируемое поле, моноширинный шрифт; при ошибке разбора - строка ошибки под полем (`canon.parse_netlist`).
- **Результат:** карточки «Тип», «fc / f0», «K», «Q» из `measure.from_output`; график АЧХ (дБ от частоты, логарифмическая ось) из `measure.read_curve`, отметка fc / f0.
- **Замечания:** `app.circuit_notes` (висящий вывод, элемент на источнике, нет выхода) и отказ модели с причиной. Новое (решение по В5, generator_v3_spec): если в запросе назван тип фильтра, а по MC12 получился другой - «в запросе назван ФВЧ, по описанным соединениям получился ФНЧ». Тип в запросе - по словарю `roles_ru.json` (как у baseline).
- **Строка состояния:** загрузка модели, время ответа, память GPU, состояние MC12.

## Устройство

- `src/mcnl/gui.py` - окно; вычисления только через `app.run` и его части, своей логики схем в окне нет.
- Модель загружается один раз, в фоновом потоке при выборе переводчика (около 30 с); запрос и расчёт MC12 - тоже в фоне, окно не замирает; результат передаётся в главный поток через очередь (`after`).
- Окружение: baseline работает в обычном Python 3.12; для модели - `venv-hf` (torch, transformers). Запуск - `.bat` на рабочем столе, как у `demo.py`.
- Рабочая папка `out/gui` (обычная папка: MC12 не видит перенаправленные папки приложения Claude).
- Тесты: разбор и подготовка данных для окна (тип в запросе против измеренного, точки графика) - без GUI; само окно - запуском.

## Проверка шагов 1-2 (07.11.2026)

Без участия человека (окно создаётся, кнопки вызываются из сценария, вид - снимком окна): Qwen3.5-4B грузится 36 с (GPU 3,2 ГБ), запрос Саллена-Ки построен верно за 19-20 с вместе с MC12, карточки ФНЧ / 1,12 кГц / 0,0 дБ / Q 0,74; пересчёт правленого нетлиста (RC ФНЧ 1 кОм, 100 нФ) - 0,6 с, fc 1,59 кГц; baseline пример с ролями «(ОС)» не разобрал - ожидаемо. Найдено и исправлено: строка состояния обращалась к torch во время его импорта в другом потоке и останавливала опрос очереди; окно без учёта масштаба Windows (125%) было размытым; глубокий спад ниже шкалы рисовался ложной полкой - теперь кривая обрывается.

Запуск:  `..\venv-hf\Scripts\python.exe src\mcnl\gui.py`  (из корня репозитория).

## Питание: от сети и от батареи (07.11.2026, ноутбук автора)

Один и тот же замер: загрузка Qwen3.5-4B, 6 запросов dev по одному (как в окне), один полный прогон с MC12.

| | От сети | От батареи |
|---|---|---|
| Загрузка модели | 45 с | 47 с |
| Ответ модели, среднее без первого (разброс) | 15,6 с (11-27) | 38,0 с (27-62) |
| Запрос целиком с MC12 | 26 с | 62 с |
| GPU под нагрузкой | 27-49 Вт, до 1,85 ГГц, P0 | 16-19 Вт, около 1 ГГц, P5 |
| Заряд | - | 100 -> 92% за прогон (около 6 мин) |

От батареи работает, но в 2,4 раза медленнее: драйвер ограничивает мощность видеокарты (около 17 Вт), процессор тоже притормаживается. Загрузка GPU и от сети часто около 40%: часть вычислений гибридного внимания Qwen3.5 идёт запасным путём (ядра `causal_conv1d`, `flash-linear-attention` не установлены; под Windows без Triton). Для показа макета нужна зарядка. Время ответа зависит от длины запроса (первый запрос dev длинный).

## Вкладка «Правила» (07.11.2026)

Что умеет программа, как писать запрос (элементы и номиналы с единицами, соединения или название типовой схемы, откуда снимать выход, питание ОУ не нужно), когда программа откажет, что делать с результатом. Четыре примера с кнопкой «В запрос» (переносит пример на вкладку «Схема»): RC-цепочка по соединениям, инвертирующий усилитель по ролям, RC ФНЧ с добавкой и выходом за ней, отказ «ФНЧ на 1 кГц». Все примеры и ещё два (ФНЧ Саллена-Ки, транзисторный усилитель) проверены на Qwen3.5-4B и MC12: схемы верны, отказы с верным кодом (`out_of_class`, `needs_design`).

## Замечание о расхождении названия и расчёта (07.11.2026)

`app.named_type` находит в запросе один названный тип фильтра (ФНЧ / ФВЧ / полосовой / режекторный, русские и английские названия, двойное Т); если названо несколько разных (каскад «ФВЧ -> ФНЧ») или ни одного - замечания нет. `app.name_mismatch` сравнивает его с типом АЧХ по расчёту MC12, `app.run` добавляет замечание к остальным; окно показывает его в «Замечаниях». Схема строится по соединениям и номиналам (В5), замечание только предупреждает.

Проверка на эталонах (верных схемах) dev, test, train v2 и C01: тип назван в 903 запросах, расхождение - в 26. Из них 25 - схемы с добавками, где добавка честно меняет тип (режектор с RC на выходе ведёт себя как ФНЧ); поэтому текст замечания не говорит об ошибке, а просит проверить добавленные элементы. Один случай - дефект данных: парафраза train-00752 называет ФНЧ RL-цепь с R в разрыве и L на землю (это ФВЧ) - в список дефектов v3.
