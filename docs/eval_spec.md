## 2. Каноническая форма нетлиста

Цель: у каждой схемы ровно одна запись-эталон, чтобы обучение не тратилось на перестановки. Оценка от канона не зависит (раздел 5), канон нужен для меток обучения.

- **Элементы и выводы** (класс A/A′): `R`, `C`, `L` (2 вывода, порядок не важен), `V`, `I` (+, −), `X ... OPAMP_IDEAL` (+, −, выход). Диоды и транзисторы - вне первой версии.
- **Имена узлов:** земля `0`, вход `IN`, выход `OUT`; внутренние - `N1`, `N2`, … в порядке обхода (ниже). Регистр - верхний.
- **Источник:** ровно один независимый источник между `IN` и `0`, плюсом к `IN`, имя `V1`. Значение - как в запросе (`DC 5`); если запрос говорит о сигнале без уровня - `DC 0`. `AC 1` ставит обвязка (раздел 4), не модель.
- **Номиналы:** инженерная запись, мантисса 1 ≤ m < 1000 без лишних нулей, суффиксы `p n u m k MEG G` (строчные, кроме `MEG` и `G`), без единиц измерения: `10k`, `4.7k`, `470`, `100n`, `2.2u`, `1MEG`. Никогда `M` (в SPICE это милли). Никогда `µ`.
- **Порядок строк:** `V`, `I`, `R`, `C`, `L`, `X`; внутри типа - по номеру. Нумерация `R1, R2, …` по порядку строк.
- **Порядок обхода для N1, N2, …:** обход в ширину от `IN`; рёбра из узла перебираются по (тип элемента, номинал, уже присвоенная метка соседа). Детерминированность для выхода генератора обязательна; единственность для симметричных схем не требуется - оценка идёт через изоморфизм.

Пример (RC ФНЧ 1 кОм / 100 нФ от источника 5 В):
```
V1 IN 0 DC 5
R1 IN OUT 1k
C1 OUT 0 100n
```

## 3. Промежуточное представление (JSON, схема `mcnl.ir/1`)

```json
{
  "schema": "mcnl.ir/1",
  "elements": [
    {"type": "V", "nodes": ["IN", "0"], "dc": "5"},
    {"type": "R", "nodes": ["IN", "OUT"], "value": "1k"},
    {"type": "C", "nodes": ["OUT", "0"], "value": "100n"},
    {"type": "OPAMP", "nodes": ["N1", "N2", "OUT"]}
  ]
}
```
- `type`: `V`, `I`, `R`, `C`, `L`, `OPAMP`. `nodes` - список в фиксированном порядке выводов из раздела 2. Необязательное поле `name` (если запрос называет элемент, «R2») в оценке не участвует.
- Номиналы - строки в той же инженерной записи, что в нетлисте, а не числа: ближе к тексту запроса («100 нФ» → `100n`), меньше ошибок вида `1e-07`. Проверка - регулярное выражение схемы.
- Нетлист ↔ IR преобразуются кодом без потерь (в пределах класса A); круговое преобразование - тест.

## 4. Обвязка проверки (testbench)

Код превращает строки элементов в полный `.ckt`:
1. заголовок (первая строка - комментарий);
2. элементы; источнику, у которого `+` в `IN`, добавляется `AC 1` (DC-значение сохраняется);
3. определение `OPAMP_IDEAL`, если есть экземпляры: `E1 OUT 0 PLUS MINUS 1E6` внутри `.SUBCKT OPAMP_IDEAL PLUS MINUS OUT`. Узел `0` внутри подсхемы MC12 соединяет с глобальной землёй (подтверждено проверкой 25.10.2026: инвертирующий усилитель 1k/10k с нагрузкой - 20,000 дБ и 180° в AC, V(OUT) = −10·Vin в DC, без предупреждений; то же, что с явным опорным выводом, соединённым с `0`). Опорный вывод не нужен;
4. анализы: `.AC DEC 100 fₗ fₕ`, где [fₗ, fₕ] = [f_хар/1000, f_хар·1000], f_хар - характерная частота **эталона** (для схем без частоты, например делитель, - `.AC` 1 Гц - 1 МГц и `.OP`);
5. `.PRINT AC VDB(OUT) VP(OUT)` (и `V(OUT)` для DC);
6. `.END`.

Правило честности: диапазон развёртки ответа модели берётся из эталона, а не из схемы модели.

Точность: MC12 пишет числа с 4 значащими цифрами (`mcout`), поэтому допуски по поведению не ниже 0,1%.

## 5. Сравнение без учёта имён (изоморфизм)

`netlist_compare` сопоставляет элементы по именам - для проверки конвертера годится, для ответов модели нет (модель вправе назвать резистор R3 вместо R1).

Нужно: проверка изоморфизма двудольного графа «элементы - узлы» с метками.
- Метка элемента: тип (уровень «топология») или тип + номинал (уровень «номиналы»); номиналы равны, если отличаются не более чем на 1e-6 относительно (после разбора суффиксов).
- Роли выводов: у `R`, `C`, `L` неразличимы; у `V`, `I` - (+, −); у `OPAMP` - (+, −, выход).
- Якоря: `0`, `IN`, `OUT` отображаются только сами в себя.
- Схемы малые (до ~30 вершин): перебор с отсечениями (по меткам, степеням, якорям) на стандартной библиотеке.
- Побочный результат при несовпадении - наилучшее частичное сопоставление для разбора ошибок (раздел 7).

## 6. Измерения по классам (определения)

Все по `VDB(OUT)`, `VP(OUT)` из `.AC` эталонной развёртки; |H| в разах = 10^(VDB/20) при `AC 1` на входе.

| Величина | Определение | Классы |
|---|---|---|
| `k_dc` | |H| на нижней частоте развёртки (или `V(OUT)/V(IN)` из `.OP`) | делитель, усилители, ФНЧ |
| `k_pass` | уровень полосы: ФНЧ - |H(fₗ)|, ФВЧ - |H(fₕ)|, усилители - медиана |H| | фильтры, усилители |
| `fc` | частота, где |H| = k_pass/√2, лог. интерполяция; ФНЧ - первое пересечение снизу, ФВЧ - последнее сверху. **От уровня полосы, не от максимума** | фильтры 1-го и 2-го порядка |
| `f0` | ФНЧ 2-го порядка - фаза −90° относительно фазы в полосе, ФВЧ - +90°; полосовой - максимум |H|; режекторный - минимум | 2-й порядок, RLC |
| `Q` | ФНЧ/ФВЧ 2-го порядка - |H(f0)|/k_pass; полосовой и режекторный - f0/(f₂ − f₁) по −3 дБ от максимума (для режекторного - от уровня полосы) | 2-й порядок, RLC |
| `f_u` | частота, где |H| = 1 | интегратор, дифференциатор |
| `type` | по форме АЧХ: flat (размах < 0,5 дБ), LP, HP, BP, BS | все |

Допуски для уровня «поведение» (класс A): `fc`, `f0`, `f_u` ±0,5%; `k_dc`, `k_pass` ±0,1 дБ; `Q` ±1%; `type` - точное совпадение. Набор величин для схемы определяется её классом в эталоне.

Существующий `mcout.cutoff_3db` считает от максимума - для ФНЧ/ФВЧ с подъёмом (Q > 0,707) это другой срез (Саллен-Ки: 9895,3 против 9894,2 Гц). Заменить определением выше, старую функцию оставить под другим именем или удалить.

Реализовано в `src/mcnl/measure.py` (старая функция - `mcout.cutoff_3db_from_max`). Уточнения при реализации:
- «Фаза в полосе» для `f0` - ближайшее к фазе на краю развёртки кратное 90°. На краю (f₀/1000) фаза звена 2-го порядка ещё не дошла до асимптоты (при Q = 0,5 - на 0,11°), и `f0` смещался на 0,2% - больше допуска раздела 9. У схем класса A с идеальным ОУ асимптотические фазы кратны 90°.
- `f0` полосового и режекторного - √(f₁f₂) по точкам −3 дБ: для звеньев 2-го порядка совпадает с максимумом/минимумом АЧХ, но не зависит от шага сетки (2,3% между точками при допуске 0,5%).
- Тип АЧХ: размах < 0,5 дБ - flat; разница краёв > 10 дБ - LP/HP; иначе подъём/провал > 3 дБ относительно краёв - BP/BS.
- Проверка: на аналитических откликах с округлением до 4 значащих цифр (tests/test_measure.py) и на выводе MC12 для ФВЧ Саллена-Ки с `OPAMP_IDEAL`: f0 −0,003%, Q −0,021%, fc +0,005%, k_pass +0,007% от узлового расчёта.

## 7. Уровни оценки и отчёт

Строгие уровни, каждый требует предыдущих:

| Уровень | Проверка |
|---|---|
| S0 разбор | IR: JSON валиден по схеме; нетлист: строки разбираются, типы и число выводов верны, номиналы читаются |
| S1 запуск | `mc12run`: схема и анализ без Error (Warning допускается) |
| S2 топология | изоморфизм с метками «тип» |
| S3 номиналы | изоморфизм с метками «тип + номинал» - **основная метрика для A (exact match)** |
| S4 поведение | все измерения класса в допуске |

Дополнительно: функциональная точность = S1 ∧ S4 (схема иная, но работает так же - например, два последовательных резистора вместо одного); F1 по мультимножеству (тип, номинал); классы ошибок: синтаксис, лишний элемент, пропущенный элемент, неверный номинал, ошибка порядка в 10³ (k/MEG/m), `M` вместо `MEG` (ошибка в 10⁹), неверное подключение, перевёрнутый источник или входы ОУ.

Реализовано в `src/mcnl/score.py`, проверено golden-набором (`tests/golden/golden.json`, `tests/test_golden.py`). Найдено при проверке:
- **Малосигнальный AC с идеальным ОУ не видит знака обратной связи.** Схема с перепутанными входами ОУ даёт ту же АЧХ (при A = 10⁶ передаточная функция почти не зависит от знака A), хотя реальная ушла бы в насыщение. Поэтому функциональная точность для класса ошибки «перепутаны входы ОУ» не засчитывается. Для задачи B, где эталонной топологии нет, это открытый вопрос (раздел «Открытые вопросы»).
- Функционально верными законно оказываются, например, лишний резистор на виртуальной земле инвертирующего входа или пропущенная нагрузка на выходе идеального ОУ.
- Классы ошибок в коде: `syntax`, `extra_element`, `missing_element`, `wrong_connection`, `reversed_source`, `swapped_opamp_inputs`, `M_instead_of_MEG`, `order_1e3`, `wrong_value`, `run_error` (схема верна, но не выполнилась - ошибка обвязки), `behavior`.

Файлы: `predictions.jsonl` - `{id, model, format: "netlist"|"ir", output}`; `scores.jsonl` - по примеру: уровни S0–S4, измерения, класс ошибки; сводка - доли по уровням с 95% интервалом Уилсона, в разбивке по классам схем и уровням сложности L1–L3.

## 8. Проверка самой метрики (golden-набор)

`tests/golden/`: эталон + заранее изменённые ответы с ожидаемыми уровнями.
- должно засчитываться (S3): переименованы узлы и элементы, перемешаны строки, другой порядок выводов у R/C/L, номинал в другой записи (`0.1u` = `100n`, `1000` = `1k`);
- не должно: источник перевёрнут; входы ОУ перепутаны; `10M` вместо `10MEG`; `10m` вместо `10k`; лишний или пропущенный элемент; элемент подключён к соседнему узлу;
- функционально равны, но не S3: два последовательных 500 Ом вместо 1 кОм (S4 да, S3 нет).

Без этого набора в работе нечем подтвердить, что метрика измеряет заявленное.

## 9. Допуск эталонов в датасет

Эталон принимается, если: (1) канонизирован и проходит круговое преобразование нетлист ↔ IR; (2) запускается в MC12 без Error; (3) для топологий с формулой (раздел 10) измерения совпадают с аналитическим значением в пределах 0,1% (fc, f0, k) и 1% (Q). Измеренные значения записываются в эталон; сравнение ответов моделей идёт с измеренными, а не с запрошенными.

## 10. Аналитические формулы (для допуска эталонов)

`src/mcnl/formulas.py`: для каждой топологии L1/L2 - функция номиналы → {k, fc, f0, Q, f_u}. Начать с: делитель; RC/RL ФНЧ/ФВЧ; послед. RLC (BP на R); инвертирующий/неинвертирующий усилитель; активный ФНЧ 1-го порядка (−Rf/R1, fc = 1/(2π Rf C)); Саллен-Ки ФНЧ/ФВЧ с усилением K; MFB полосовой; интегратор с Rf. Каждую формулу проверить численным узловым расчётом (как для Саллена-Ки) и прогоном в MC12.

## 11. Статистика эксперимента (заложить сразу)

- Тест замораживается до первого обучения, фиксируется SHA-256 (v1 заморожен 25.10.2026: `data/dataset/v1/README.md`, test.jsonl `535cbb51…36ad`); деление по `circuit_id`; отдельные проверки на обобщение - неизвестные топологии, неизвестные семейства шаблонов, номиналы вне диапазона обучения.
- Размер синтетического теста 500–1000 примеров (при 300 интервал около ±5 п. п. - различия в 2-3 п. п. не видны); человеческий тест 100–200 - отдельно.
- Каждое сравнение (размер обучения 1000 / 2500, формат netlist / IR, модели) - 2-3 seed; сравнение моделей на одних примерах - критерий Макнемара.

## 12. План реализации для Claude Code

Порядок по зависимостям. Каждый пункт - отдельный модуль в `src/mcnl/` с тестами; тесты проходят перед коммитом.

1. **`canon.py`** - разбор и форматирование номиналов (раздел 2), разбор строк элементов класса A, канонизация (порядок, нумерация, узлы N1…), IR: схема, проверка, IR ↔ нетлист. *Готово, когда:* круговое преобразование на всех эталонах из tests; `10M`/`10MEG`, `0.1u`/`100n`, `1000`/`1k` разбираются верно; канонизация выхода детерминирована.
2. **`iso.py`** - изоморфизм с метками и якорями (раздел 5), режимы «топология» и «номиналы», частичное сопоставление для разбора ошибок. *Готово, когда:* проходят случаи «должно засчитываться/не должно» из раздела 8 (сами golden-файлы - пункт 6).
3. **`bench.py`** - обвязка (раздел 4) и `OPAMP_IDEAL`. Первым делом проверить в MC12, что земля внутри подсхемы - глобальная. *Готово, когда:* `rc_probe` и Саллен-Ки с идеальным ОУ, собранные через bench, дают прежние fc в MC12.
4. **`measure.py`** (или расширение `mcout`) - измерения раздела 6 и классификация типа АЧХ. *Готово, когда:* на эталонных схемах пункта 7 измерения совпадают с формулами в допусках раздела 9.
5. **`score.py`** - уровни S0–S4, функциональная точность, F1, классы ошибок, `scores.jsonl` и сводка с интервалами Уилсона (раздел 7).
6. **`tests/golden/`** - набор раздела 8 и тест, сверяющий уровни `score.py` с ожидаемыми.
7. **`formulas.py` + пилот эталонов** - формулы раздела 10 и 10–15 эталонных схем (по одной-две на топологию L1/L2), прошедших допуск раздела 9. Это первый кусок будущего генератора и проверка всего канона целиком.

После пункта 7 - спецификация генератора (топологии, выбор номиналов, шаблоны русских запросов) вместе с автором.

- ~~Земля внутри `.SUBCKT` в MC12~~ - глобальная, проверено (раздел 4).
