## Решения автора

- Пока только датасет v2. v1 обучаем потом и только при приемлемых результатах: если v2 окажется плохим, сравнение не понадобится.
- Детали фаз обсуждаются перед началом каждой фазы.
- Обучение автор запускает и наблюдает сам в Colab: ноутбук показывает ход, график потерь и примеры ответов, материалы идут в текст работы.
- Модель может быть и крупнее: работа без интернета важна, но если крупная модель окажется заметно лучше, от неё можно отказаться.
- Для пробы конвейера взят Qwen2.5 7B: без запроса доступа и с известным поведением. Это не выбор для работы; свежие модели - перед фазой 3.

## Как устроена работа

Открыть ноутбук: https://colab.research.google.com/github/xdstk/lang.cir.spice.mc12/blob/main/colab/stage2.ipynb
Репозиторий закрытый: Colab читает код по токену только на чтение из секрета `GITHUB_TOKEN`. Открытому репозиторию токен не нужен.
Любой запуск в Colab лежит на Drive в `mcnl/<RUN>`: адаптер, `run.json`, `loss.png`, ответы. Ноутбук правится через `colab/build_notebook.py`.

```
репозиторий (GitHub) -> Colab: экспорт, обучение, ответы -> predictions.jsonl на Drive
                     -> ноутбук автора: evaluate.py --predictions -> MC12 -> таблицы
```
В Colab нет MC12, поэтому модель отвечает там, а оценка идёт локально. На Drive хранятся адаптеры LoRA, ответы и метаданные запуска.

Модель пишет ровно то, что записано в датасете: канонический нетлист с источником или `REFUSE код: причина`. Системная инструкция одна для обучения и для работы программы: `src/mcnl/training.py`.

- Модель читает шаблоны и проваливается на `llm_test`: тогда нужен v3.

- Точные номиналы модель может копировать с ошибками: смотрим ошибки `wrong_value`.
- Малые модели могут плохо работать с русским.
