# Аудит выборки Masala-CHAI (batch100) и репозитория

Дата: 2026-10-24, поправка 2026-10-25. Статус: предварительный, статический аудит (симулятор в среде недоступен). Скрипт: src/mcnl/audit_netlists.py.

## Выборка
100 троек подпись + SPICE + (10 изображений), id 5520-5619 подряд. Это один непрерывный блок, а не случайная выборка: доли классов ниже относятся к нему, а не ко всему датасету.

Состав блока (по типам элементов): ОУ/подсхемы/зависимые источники 50, пассивные цепи 32, диоды 19, транзисторы 2. Медиана 6 элементов на схему, максимум 13. Дубликатов нетлистов нет.

## Результаты статических проверок
Уровни: A - нет структурных дефектов (с оговорками), B - нужен тестовый стенд или модель ОУ, C - есть дефект, мешающий запуску или искажающий смысл.

- A: 5, B: 10 (1 + 9), C: 85.
- Доверительный интервал (Уилсон, 95 %) для доли C: 76.7-90.7 %; для доли A: 2.2-11.2 %.
- Топология нарушена (висячий вывод пассивного элемента, нет узла 0, элемент замкнут сам на себя, нет пути по постоянному току, битая строка): 69.
- Нет чисел или определений (параметры вида R1_value, `<value_of_vs>`, неопределённая модель): ещё 16.
- Частые дефекты: висячие выводы пассивных элементов 50, неопределённые параметры 51, нет узла 0 в 32, остаток ограждения markdown в первой строке 78, нет .end 61, нет анализа 96 (последние три чинятся автоматически).
- 44 из 100 нетлистов вообще не содержат числовых номиналов R/C/L.

**Поправка (MC12 Reference Manual, FLOATING_NODES_CHECK):** узлы с одним подключением не мешают симуляции в Micro-Cap. Флаг «висячий вывод» для MC12 означает смысловой дефект, а не ошибку запуска. Точное число записей C без этого флага надо пересчитать.

## Смысловая проверка (чтением, без симуляции)
Из 5 записей уровня A: 5558 (выход ОУ тождественно 0 В из-за источников 0 В на входах), 5577 (перевёрнута полярность управления в подсхеме ОУ, обратная связь положительная), 5596 (ОУ включён неверно, подсхема пустая), 5600 (источник тока 0 А разрывает цепь, ток нулевой) содержат ошибки; 5610 правдоподобна, подпись описывает несколько панелей рисунка, проверить нельзя. С картинками сверены 5522 и 5525: топология нетлиста не совпадает с рисунком. Вывод: структурная проверка необходима, но недостаточна; нужна проверка по поведению.

## Подписи
- Подписи сгенерированы GPT-4o (по README репозитория) и описывают рисунок: 53 из 100 ссылаются на номер рисунка, 74 содержат LaTeX.
- Числа R/C/L из подписи совпадают с нетлистом: 74 из 128; у 17 из 51 подписей с числами совпадений нет. Номиналы нетлиста присутствуют в подписи: 90 из 168.
- Подпись 5522 описывает два ОУ и номиналы, которых нет на рисунке (один ОУ, символьные обозначения).

## Репозиторий jitendra-bhandari/Masala-CHAI (коммит от 2026-08-08)
- Папка Dataset содержит только изображения (около 1 800 файлов), без нетлистов и подписей. README: «Updated dataset will be available soon».
- Файла LICENSE в корне нет (лицензия не указана; перед использованием уточнить у авторов).
- analoggenie.jsonl: 2 950 пар «описание -> нетлист» в чат-формате. Нетлисты в стиле Spectre/Cadence (`M0 (net1 net2 VSS VSS) nmos4`), не в SPICE; числовых значений нет ни в одном; 2 823 из 2 950 содержат MOSFET (около 79 % всех строк); в 1 909 повторяются имена экземпляров. Для MC12 напрямую не пригоден.

## Решение (предложение)
Основной корпус - синтетический генератор целевого класса с эталоном, гарантированно запускаемым. Masala-CHAI не использовать как мерило качества; максимум - источник разнообразия формулировок после фильтра. Тест - реальные формулировки (от людей).

## Не проверено
- Запуск в ngspice и MC12.
- Лицензия набора на Hugging Face, из которого взята выборка.
