# Micro-Cap 12: формат .CIR, пакетный режим, конвертер схема → SPICE

Дата: 2026-10-25. Статус: прототип; .CIR → SPICE совпадает с File → Translate самого MC12 на 6 схемах (топология и номиналы); пакетный запуск .ckt и разбор .ANO/.TNO работают, результат сходится с теорией (RC −0,001%, Саллен-Ки с идеальным ОУ −0,03%); из 79 нетлистов DATA запускаются 66; генерация .CIR проверена в MC12 пользователем на RC-фильтре.
Источники: MC12 User's Guide (ug12.pdf), MC12 Reference Manual (rm12.pdf), примеры OPAMP1.cir, Sallen-Key_High_Pass_Filter.cir, Counter.cir (tests/data).

## Подтверждено руководством
- Пакетный режим: `MC12 @файл.bat`; строка `имя [/DEF "x val"] [/NOF "fn"] /T|/A|/D …` (UG12, с. 43–46). Есть также /quiet, /SVI (UG12, с. 20, только в списке новшеств) и команды сохранения картинок (/IC, /IA). Ключа экспорта нетлиста нет. Поведение на деле - раздел «Пакетный запуск» ниже.
- Экспорт в SPICE только из меню: File → Translate → Schematic to SPICE Text File (RM12, с. 84).
- SPICE-файл (.ckt): пределы анализа из `.TRAN`/`.AC`; `.PRINT` пишет численный вывод в ИМЯ.TNO/.ANO/.DNO (RM12, с. 940).
- Подсхемы/модели для SPICE-файла: текст → `.LIB` → неявный `.LIB NOM.LIB` (RM12, с. 748). Библиотечные ОУ работают в MC12, но не переносятся в ngspice.
- Правила соединений: конец провода соединяется с концом, выводом или внутренней точкой провода; пересечения внутренних точек не соединяют; текст с якорем на узле именует узел; одинаковые имена соединены; Ground = узел 0 (RM12, с. 46–47, 68). Поправка (проверено 03.11.2026): при загрузке файла MC12 соединяет провод только концом с концом или с выводом; Т-примыкание конца провода к середине другого в файле не соединилось (предупреждения о висячих узлах). Правило про внутреннюю точку, видимо, относится к рисованию в редакторе, который сам режет провод. cir2spice читает мягче, по руководству.
- Узлы с одним подключением в MC12 не ошибка (FLOATING_NODES_CHECK, RM12, с. 80).
- OPAMP (модель OPA, уровни 1–3) и Pulse source (модель PUL) существуют только в схемном формате; SPICE-синтаксиса нет (RM12, с. 727–728, 734–735). Но File → Translate разворачивает OPAMP всех трёх уровней в SPICE-подсхемы (уровень 2 - двухполюсная на G-источниках, уровень 3 - модель Бойла на транзисторах), см. ниже.
- OPAMP уровня 1: R = ROUTAC+ROUTDC, GM = A/R (RM12, с. 732); умолчания A=2E5, ROUTAC=75, ROUTDC=125 (с. 728).
- Схема может содержать целый SPICE-нетлист между `.SPICE`/`.ENDSPICE`, и тогда MC12 хранит настройки анализа (RM12, с. 25).

## Формат .CIR (восстановлен по примерам)
- Текстовый INI-подобный формат: [compdef] (имя, Definition, выводы `Pin="имя",x,y,…` в шагах сетки), [Comp] (Name, Px/Grid, Rot) с последующими [Attr] (PART, VALUE, RESISTANCE, MODEL…), [Wire] (Pxs/Grids), [Grid Text], [Text Area] (модели, .DEFINE), [Limits] и [WaveForm] (пределы и графики анализов).
- MC12: координаты `Px=` в пикселях, шаг сетки 8 px; MC10: `Grid=` в шагах.
- Rot 0..7: 0–3 поворот на 90°·k ((x,y)→(−y,x) за шаг), 4–7 то же с отражением y→−y. Подтверждено в MC12 для двухвыводных элементов (Rot 0, 1, 3, 7) и сверкой с Translate для MOSFET с Rot 0, 4, 6 (MOSDIFF); Rot 1, 2, 3, 5, 7 у многовыводных не проверены.
- Многострочные Grid Text в примерах DATA содержат описание схемы на естественном языке («This circuit compares…»), возможный дополнительный источник текстов.

## Генерация .CIR (обратное направление), проверено в MC12 25.10.2026
- Минимальный файл (~250 строк вместо 1400–2000): [Main], нужные [shapedef]/[compdef] (скопированы из образца), [Circuit] из 4 полей, [Comp]/[Attr], [Wire], [Grid Text], [Section], [Page], [Limits], [WaveForm]. Служебные секции окон, шрифтов и панелей не нужны. В заголовке `Key ID=0`, `NLCnt=0`, `TXCnt=0` MC12 принял.
- RC-фильтр НЧ (1 кОм, 100 нФ) с проводами: MC12 открыл без ошибок, нумерация узлов верная, AC: −2,99 дБ в точке ~1,6 кГц. Теория: fc = 1591,5 Гц; ближайшая точка сетки 101/декаду 10^3,2 = 1584,9 Гц даёт −2,992 дБ, что совпадает с показанием.
- Вариант без проводов, только метки узлов на выводах: открывается, AC-анализ запускается и корректен; отличие только в отсутствии проводов на чертеже. Значит, разводку проводов можно не решать: соединения задаются метками.
- Круговая проверка: сгенерированный .CIR → cir2spice → netlist_compare с эталоном = совпадение топологии и номиналов.

## spice2cir: нетлист класса A -> .CIR для пользователя (проверено 25.10.2026)
`src/mcnl/spice2cir.py`; описания фигур и элементов - `data/cir_templates.cir` (извлечены из Sallen-Key_High_Pass_Filter.cir, OPAMP1.cir, DATA/CHOKE.cir, подфигуры собраны рекурсивно по `Root=`).
- Раскладка простая: источник слева (плюс к IN), двухполюсники сеткой, ОУ ниже; провода не рисуются, соединения - метками узлов на выводах (так было до 03.11.2026; теперь провода есть, см. раздел «Чертёж»); на узел 0 - символ земли. В схеме - текст с исходным нетлистом и анализ AC в диапазоне обвязки (±3 декады вокруг f_хар) с графиком dB(V(OUT)).
- ОУ - элемент Opamp с моделью `OPAMP_IDEAL` уровня 1 (A = 1e6, ROUTAC + ROUTDC = 1 Ом). Выводы питания - на землю: неподключённые дают предупреждение «Nodes have no DC path to ground. Resistors added», а у уровня 1 питание на передачу не влияет. `cir2spice` переводит такой ОУ обратно в `X … OPAMP_IDEAL` (3 вывода).
- Формат текстовой области зависит от версии файла: у версии 10.01 (наш заголовок, как в Sallen-Key) - строки `Text=…`; формат «`Len=N` + сырой текст» - у версии 9 (DATA/CHOKE.cir), в файле версии 10 MC12 его не читает («Extra or unknown data was found»). Блок `[Text Area]` должен стоять после `[Section]`/`[Page]`: раньше них - «Bad format in loading file».
- Проверка: круговое преобразование нетлист -> .CIR -> cir2spice -> нетлист совпадает (изоморфизм по номиналам) на 19 пилотных эталонах и всех 500 схемах замороженного test; 19 пилотных и 3 каскада L3 загружаются и считаются в MC12 пакетом без сообщений в журнале; ФВЧ Саллена-Ки открыт в MC12 на экране - 40 дБ/дек, полоса +6 дБ (K = 2), излом около 10 кГц, как по расчёту.
- Попутно в `mc12run.parse_doc`: строка «Error Bad format in loading file '…\X.CIR'» не начинается с имени схемы и приписывалась предыдущей; теперь относится к схеме из самой строки.

## Прототип (src/mcnl/)
- cir2spice.py: .CIR → .ckt; R, C, L, батарея, источники V/I, PULSE (из PUL), SIN (из Sine source), NFV, ключ S, соединитель Tie, диод, BJT, MOSFET, подсхемы, OPAMP (эквивалент уровня 1 с предупреждением для уровней 2–3); цифровые элементы помечаются как неподдерживаемые.
- mc12run.py: пакетный запуск списка .ckt одним вызовом MC12, таймаут со снятием процесса, разбор журнала .DOC в статус по каждой паре схема-анализ.
- mcout.py: разбор .ANO/.TNO/.DNO в столбцы; `cutoff_3db` - частота среза по уровню −3 дБ от максимума (логарифмическая интерполяция).
- netlist_compare.py: совпадение топологии без учёта имён узлов (R/C/L без ориентации) и номиналов; годится и для проверки конвертера, и как метрика при оценке моделей.
- make_test_cir.py: генерация тестовых .CIR (пока жёстко заданный RC-фильтр).
- audit_netlists.py: аудит Masala-CHAI.
- tests/test_primitives.py: синтетические схемы с заранее известным ответом (Tie, Sine, S, NFV, старый формат, пустой номинал, выражение в номинале) и CHOKE из DATA (пропускается, если MC12 не установлен).
- tests/test_roundtrip.py: OPAMP1 и Sallen-Key против эталонов File → Translate (заменили ручные эталоны, которые оказались неполными); MOSDIFF, CHOKE, S_BUCK_CM, BAX против Translate (читают .cir из C:\MC12\DATA, иначе пропускаются); RC_test_* против ручных эталонов; Counter отклонён. Всего 20 тестов, все проходят.

## Пакетный запуск и числовой вывод (подтверждено проверкой 25.10.2026)
Исполняемые файлы: `C:\MC12\Micro-Cap 12.exe` (64 бит, x64) и `C:\MC12\mc12.exe` (32 бит). Обе версии в пакетном режиме ведут себя одинаково: сами закрываются, принимают глобальный /quiet, пишут тот же формат вывода (в шапке «(32 bit)» / «(64 bit)») и тот же журнал ошибок; на rc_probe, sk_ideal и bad_probe результаты совпали (fc 1591,53 и 9892,67 Гц, та же ошибка модели). Значит, конвейер годится и для 32-битных машин в учебных аудиториях. Обёртка - src/mcnl/mc12run.py, разбор вывода - src/mcnl/mcout.py.
- `"Micro-Cap 12.exe" /quiet @пакет.bat`, строки `полный_путь.ckt /A`: MC12 сам закрывается, около 1 с на пакет из нескольких схем (79 схем DATA, 123 анализа - 23-28 с). Код выхода всегда 0, в том числе при ошибках.
- `/quiet` принимается только глобально перед `@пакет`; в строке схемы - «Error in command line '/QUIET'».
- Ошибки не вызывают окон: тип (Error/Warning), текст, элемент и файл пишутся в `<пакет>.DOC` рядом с .bat, следующие строки пакета выполняются. Предупреждение («Node X has no DC path to ground. Resistor added.») прогон не прерывает.
- Числовой вывод `.PRINT` - в `ИМЯ.ANO/.TNO/.DNO` рядом с .ckt; рядом же MC12 создаёт `ИМЯ_ckt.inx`. `/NOF "имя"` без полного пути пишет в `C:\MC12\DATA` (не использовать), с полным путём - куда указано.
- MC12 не видит перенаправленные папки приложения Claude (AppData\Roaming в пакете MSIX); рабочие файлы - в out/ проекта.
- Для схемы .cir без `.PRINT` в выводе есть только рабочая точка, таблицы нет; поэтому конвейер работает с .ckt.
- Формат вывода (восстановлен по примерам): шапка из звёздочек («AC Analysis of ИМЯ»), блок Limits (значения выровнены по одному столбцу, у самого длинного ключа отступ в один пробел), баннер прогона (`Temperature=27`), «DC Operating Point Voltages» (пары узел-напряжение, только для схем), «Interpolated Waveform Values»: строка имён, строка единиц, числа с 4 значащими цифрами, `NA` - нет значения.
- Проверка по теории: RC-фильтр 1 кОм / 100 нФ - fc 1591,53 Гц против 1591,55 Гц (−0,001%); ФВЧ Саллена-Ки (K=2) с идеальным ОУ (E-источник) - 9892,7 Гц против 9895,3 Гц узлового расчёта (−0,03%, в пределах 4 значащих цифр). Срез здесь считается на −3 дБ от максимума в окне развёртки; при Q = 0,713 у этого фильтра есть подъём (максимум 2,00024 вместо 2), и от уровня полосы пропускания срез 9894,2 Гц. Для фильтров с заметным подъёмом (Чебышёв) эти определения расходятся сильнее - определение нужно зафиксировать в метрике. С библиотечной моделью AD711 - 9834 Гц (−0,6%) и усиление в полосе на 0,05 дБ ниже: вклад макромодели ОУ, не конвейера.
- Прогон на объёме выявил то, чего не видит сравнение топологии: из 79 нетлистов DATA, совпавших с MC12 по топологии, сначала запускались 34. Исправлено:
  - `AC 1` должен стоять до функции источника (`V1 1 0 AC 1 DC 0 PULSE(...)`), иначе «Extra text 'AC' found» (42 анализа);
  - строки-продолжения `+` у переведённых моделей OPA/PUL/SIN оставались незакомментированными;
  - `.PRINT` брался из графиков схемы, где узлы указаны номерами MC12, не совпадающими с нашими; теперь в `.PRINT` только узлы, которые есть в нетлисте.
  Итог: запускаются 66 из 79. Остальные 12 - вне целевого класса: `.ARRAY` в SPICE-файле («Unknown command», ARRAY1, Batch), символ `.DEFINE` вместо значения источника (MIXER1, Voltage_Source), ток через элемент `I(HB)` в формуле (F2), нет определения UA741 (subckt1), «Matrix is singular» (smith - ВЧ-демонстрация с HUGE в номиналах; A_FLYBACK), «Internal time step too small» (S_BUCK_SYN).

## Сверка с File → Translate (25.10.2026)
Порядок: копия .cir в обычную папку (оригиналы DATA не трогаются) → MC12 → File → Translate → Schematic to SPICE Text File, тип Micro-Cap Spice, Transient + AC, Expand SUBCKT → netlist_compare. Эталоны лежат в tests/reference (первая строка с локальным путём заменена заголовком).

| Схема | Что проверяет | Итог |
|---|---|---|
| MOSDIFF | MOSFET Rot 0/4/6, Tie (подложки VDD/NB) | совпало с первого раза |
| OPAMP1 | PULSE, OPAMP уровней 1–3 | совпало после исправлений 1, 2 |
| Sallen-Key | VSpice с SIN, библиотечная подсхема AD711K_AD | совпало |
| CHOKE | старый формат, два Sine source | совпало после исправления 3 |
| S_BUCK_CM | NFV, ключ S, библиотечная подсхема PWMCM | совпало после исправления 4 |
| BAX | Tie, Sine, номинал-выражение | совпало (исправление 5 - форма записи) |

Что показала сверка и что исправлено:
1. PULSE: MC12 пишет `AC 1 DC <VZERO> PULSE(...)`; добавлен `DC VZERO`. `AC 1` пишется только при включённом в диалоге AC.
2. OPAMP уровня 1: подсхема MC12 - RSUPPLUS/RSUPMIN 1 Ом на питании, ROUT = ROUTAC+ROUTDC, GOUT = A/ROUT, RIN 1 ГОм. Наш эквивалент брал ROUT = ROUTDC без RIN; приведён к подсхеме MC12. Уровни 2–3 MC12 тоже разворачивает в подсхемы; у нас по-прежнему эквивалент уровня 1 с предупреждением - расходится с MC12 по поведению, не по топологии верхнего уровня.
3. Sine source: RS моделируется последовательным резистором со стороны плюса через внутренний узел (`V1 INTERIOR 0 SIN(...)`, `RV1 1 INTERIOR 0.001`). Перенесено так же (узел `<имя>_RS`); при RS=0 резистора нет.
4. Порядок выводов подсхемы - порядок узлов в `.SUBCKT`, а не порядок выводов в compdef (у PWMCM compdef 3,4,6,5,2,1 при `.SUBCKT PWMCM 1 2 3 4 5 6`; у AD711K_AD - `13 15 12 16 14`, без закономерности). Теперь порядок берётся из .SUBCKT в тексте схемы, иначе из библиотеки MC12 в порядке NOM.LIB (переменная MC12_LIBRARY, по умолчанию C:\MC12\LIBRARY); при нескольких определениях выбирается первое с тем же набором узлов (PWMCM есть в On_Semi.lib и power456.lib). В DATA так было неверно 56 из 116 вызовов подсхем в 40 файлах - молча неверная топология. Не найдены определения для 2 вызовов (dig_power: 7404_P, subckt1: UA741) - предупреждение.
5. Номинал-выражение MC12 берёт в фигурные скобки (`{10K-R(R1)}`); теперь так же.
- Узлы: метки Grid Text MC12 сохраняет как имена (Vout, In1), а Tie - нет (в BAX «C» и «Vee» стали номерами). Для топологии не важно; совпадение имени Tie с меткой по-прежнему не проверено.
- `Sweep type=Auto` в MOSDIFF MC12 переводит в `.AC LIN 49`, у нас `.AC DEC`; пределы анализа netlist_compare не сравнивает - отдельный вопрос.
- netlist_compare доработан: первая строка - заголовок (у Translate это путь C:\...), комментарии `;`, источники V/I сравниваются по (DC, AC, функция, аргументы) независимо от порядка записи.

## Прогон cir2spice по всей DATA (25.10.2026)
- Итог после поддержки Sine source, Tie, S, NFV и старого формата: 191 файл, сбоев нет. Без ошибок 83 (из них 4 без компонентов: 2403, 3d1, Flowchart1, Flowchart_Lamp), ошибки только из-за аналоговых примитивов 17 (Tline 6, LFVofV 4, User source 2, WAV File Source 2, NTVofV, N_PORT, Switch), аналоговые + макросы 42, цифровые/анимированные/прочие 49. Первый прогон: без ошибок 49.
- Старый формат .CIR (63 файла, заголовок `Grid=` вместо `Px=`), восстановлен по примерам:
  - атрибут одной строкой `ONV=x,y,ИМЯ,ЗНАЧЕНИЕ` вместо пары `ON=`/`V=`; в значении бывают запятые (`V(In,Switch)`). Раньше в этих файлах молча терялись все PART и номиналы (`R_U? 0 A` без сопротивления);
  - [Text Area]: служебные ключи, `Len=N`, затем сырой текст без префикса `Text=`. Раньше терялись все .MODEL/.DEFINE текстовой области.
  Теперь пустой номинал R/C/L - ошибка, а не тихий пропуск.
- Перевод примитивов (подтверждено руководством, кроме Tie):
  - Sine source → `V + - SIN(DC A F 0 θ PH°) AC 1`, θ = 1/TAU; PH в модели в радианах (RM12 с. 745). RP (повтор затухания) в SPICE SIN не выражается - предупреждение; RS - последовательный резистор (см. сверку с Translate).
  - Pulse и Sine source дают в AC-анализе фиксированные 1 В (UG12 с. 100, RM12 с. 220), поэтому к PULSE и SIN добавлено `AC 1`; раньше у PULSE его не было.
  - S → `S po mo pc mc модель`, .MODEL VSWITCH переносится как есть (RM12 с. 740-742).
  - NFV → `E + - VALUE = {формула}` (RM12 с. 562, 577-578). Формула остаётся в синтаксисе MC12 (T - время и т.п.): для MC12 годится, для другого симулятора нужен перевод. Атрибут FREQ не переносится (предупреждение).
  - Tie (и "Output Port" с тем же Definition) в руководствах не описан. По примерам: однополюсник, все Tie с одинаковым PART - один узел; подтверждено Translate на MOSDIFF и BAX. Совпадение имени Tie с меткой Grid Text считается тем же узлом (без учёта регистра) - в DATA таких случаев нет, не проверено.
- Rot=4 у M6 в MOSDIFF: по кодировке сток M6 оказывается на NB, что выглядело подозрительно; Translate показал то же самое (`M6 4 9 7 4`), то есть так нарисовано в схеме, а кодировка верна.
- Найдено и исправлено при прогоне (восстановлено по примерам DATA):
  - диапазон Transient записан как `TMax=` (110 файлов) или `TRange=` (81 файл); раньше `.TRAN` терялся во всех файлах с `TRange`;
  - вывод подложки MOSFET в compdef называется `Body`, не `Bulk`; раньше все MOSFET отбрасывались;
  - AC: `Sweep type=List` (FRange - список частот) не переводится в `.AC`, предупреждение; `Linear` → `.AC LIN`;
  - `NPts` бывает с суффиксом (`1k`).
- Блокирующие аналоговые примитивы (число файлов, где они единственная причина): S (ключ, 14), Tie (14), NFV (функциональный источник, 13), Sine source (11), Tline (6), отсутствующая .MODEL PUL (4), LFVofV (4), прочие по 1-2. Tie влияет на топологию (подключает выводы к именованным узлам), его пропуск даёт неверный нетлист, поэтому файл считается ошибочным.
- Сверены с Translate: MOSDIFF, CHOKE, S_BUCK_CM, BAX, OPAMP1, Sallen-Key. Следующие кандидаты: circuit3, prlc, modelrlc, rise, RCdef, RCdefNOEQ, COLPITTS, GUMMEL, CARLO4, Asymmetric_Tolerances, DIFFAMP, GILBERT, MIXER1, RCA3040, ECLGATE, dist_demo1, CMOS, MOSCAPS; плюс схемы с многовыводными элементами при Rot 1, 2, 3, 5, 7 и один из 40 файлов с переставленными выводами подсхем (например, A_BUCK_CM).

## Архитектурное решение
Модель генерирует SPICE-нетлист; .CIR строит детерминированный код (раскладка + метки узлов, провода опционально). Модель координат не касается. Метрики сравнения моделей считаются по нетлисту.

## Открытые вопросы
- Сверка с Translate ещё на 10–15 схемах (список выше), включая Rot 1, 2, 3, 5, 7 у многовыводных.
- OPAMP уровней 2–3: MC12 разворачивает их в подсхемы; повторить это по формулам RM12 (с. 732–) или оставить эквивалент уровня 1.
- `.AC` для `Sweep type=Auto`: MC12 пишет LIN, мы DEC; netlist_compare пределы анализа не сравнивает.
- Вывод с несколькими прогонами (шаг параметра, список температур, Монте-Карло) парсером не проверен: в целевом конвейере не нужен.
## Дизайнер фильтров: подключение через Active.flt (проверено 01.11.2026)

## Чертёж: текст и масштаб (проверено в MC12 12.2.0.5, 03.11.2026)
- Многострочный Grid Text привязан за нижний левый угол: блок из N строк в Grid=2,2 уходит выше листа, видна одна последняя строка. JustifyV=Top (как в DATA/Batch.cir) в нашем файле не сработал ни с Grid=, ни с Px=. Поэтому spice2cir ставит блок справа от схемы и опускает точку привязки на высоту блока.
- Масштаб окна схемы задают поля `Scale 0..3` страницы Main (`[Page]` с Index=0): единиц чертежа на пиксель, меньше 1 - крупнее. `[Schematic] Scale` при загрузке не читается.
- MC12 принимает только свои шаги масштаба: 0.5, 2/3 и 2 сработали, 0.6, 0.95 и 1.5 молча заменены на 1. Окно открывается с верхнего левого края содержимого, а не с начала листа; при масштабе 1 видно около 155 x 60 шагов сетки (ноутбук автора, развёрнутое окно).
- Раскладка с 03.11.2026: последовательные двухполюсники - горизонтально строками; элементы на землю - вертикально (Rot 1 или 3, земля снизу); ОУ ниже, земли питания над и под ним; земля всегда смотрит от элемента наружу (линия земли (12,0) px, Rot 0-3 - вправо, вниз, влево, вверх). Метки к выводам слева и снизу ставятся на конце короткого провода `[Wire] Grids=x1,y1,x2,y2`, иначе метка ложится на элемент. Земля на входе ОУ - на конце отвода, вниз.
- Проверено: spice2cir.overlaps не находит наложений ни в одной из 3466 схем v2; все 3466 чертежей читаются cir2spice в ту же топологию с номиналами; 10 чертежей dev MC12 открыл и посчитал (AC) без сообщений, кроме предупреждения о висячем узле у схемы, где он есть в самом нетлисте.
- Провода с 03.11.2026 (spice2cir.draw, route.py): цепи разводятся по одной на сетке A* с ценой изгибов и пересечений, от короткой к длинной; чужую цепь провод только пересекает под прямым углом, не поворачивая и не заканчиваясь на ней; через выводы, точки меток, корпуса и подписи не проходит. Провода режутся во всех точках примыкания (`_split_at_joints`), так что каждое соединение - конец к концу или конец к выводу. Метки остаются только IN и OUT; неразведённая цепь получила бы метки на выводах, как раньше.
- Проверено: разведены все 12006 цепей 3466 схем v2, наложений нет, cir2spice читает ту же топологию; тест `test_wires_connect_only_at_ends` проверяет связность по строгому правилу MC12 (PILOT, test v1 и v2). В MC12 посчитаны все 717 различных схем test, gen_topology и dev v2: АЧХ и ФЧХ чертежа совпали с эталонным .ckt, предупреждения - те же, что у эталона (висячие по постоянному току узлы самих схем). Два исключения со схемами на ОУ (test-00068: до 6,7 дБ ниже −76 дБ; dev-00060: 0,63°) - от выходного сопротивления модели ОУ в .CIR (ROUTAC=0.5) против идеального E-источника обвязки: тот же чертёж без проводов даёт ту же кривую до цифры.
- Раскладка по пути сигнала с 03.11.2026 (spice2cir._flow_layout): главная линия - простой путь IN -> OUT с наибольшим числом ОУ, затем кратчайший; в узел, который ведёт ОУ, путь входит только через этот ОУ. Источник слева, элементы на землю и боковые цепочки висят под узлом, ОУ - в разрыве линии выходом на ней, обратные связи - перемычками над линией (подписи над элементом), делитель обратной связи - под ОУ. Если сигнал идёт на минус, ОУ отражён по вертикали (Rot=4, минус сверху). Выводы R, C, L равноправны (iso), поэтому вместо поворота на 180° переставляются узлы. Вне правил (несколько источников, ОУ вне линии, несвязная схема) - прежняя сетка.
- Проверено: все 3761 различные схемы v2 (с train) раскладываются по пути сигнала, всё разведено, без наложений, строгая связность и обратное чтение верны. В MC12 все 717 схем test, gen_topology и dev дали ту же АЧХ и ФЧХ, что эталон (кроме двух случаев модели ОУ выше), - значит, Rot=4 у ОУ MC12 понимает так же, как cir2spice: у инвертирующих схем при перепутанных входах фаза разошлась бы на 180°. Подписи перемычек и ОУ на снимках MC12 стоят на своих местах (инвертирующий, Саллен-Ки ФВЧ с усилением, Tow-Thomas).
